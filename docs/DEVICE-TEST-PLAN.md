# Moving Traveler — device test plan

**Status: planned, not performed by this document.** Updated 15 September 2026 for version **1.4.0 / code 5**, adding saved-key controls, distinct route choices and up to six ordered vias over the MapLibre/OpenFreeMap/Geoapify implementation. Record actual results against the exact tested artifact. Desktop previews and automated fixture tests do not establish Android mock-provider delivery, live provider access or WhatsApp compatibility. Credential fixtures use real AES-GCM with a substituted key provider; they do not exercise a phone's Android Keystore. Recorded results belong in `docs/VERIFICATION.md` or an attached device report. These cases must be observed before making corresponding release claims; the document does not establish Play Store approval or readiness.

## Test record

For each run record: artifact SHA-256, application ID/version code, signing fingerprint, install source, device/OEM, Android/API, Play Services version or absence, MapLibre renderer, personal/shared key access model (never the key itself), provider mode, battery settings, date, steps, expected/observed results and evidence. Do not mark a case passed without observing it. Prepare personal routing access using [Routing setup](ROUTING-SETUP.md). Live provider checks require a real account key; fixture responses do not establish account access. Preserve failures and retest after fixes.

Run the core cases on every listed API. Include a Google Play Services device, a device/emulator without it, a low-memory/small-screen device, and at least two real OEM families. At least one real OEM device must complete the 60-minute screen-off test below with its ordinary default power settings. Record exceptions rather than claiming all-OEM reliability.

## Functional and system cases

| Case | Steps and acceptance criteria |
| --- | --- |
| Fresh start and upgrade | Clear storage and launch. No online map/search/route request precedes OpenFreeMap/Geoapify consent. Choose coordinates only and run Direct line. Upgrade from the prior Google version: require the new provider choice. Then enable online planning with no Geoapify key: OpenFreeMap should load and map points/direct paths should work. Set up routing must open key entry, not begin playback. Declining optional coarse/notification permission must still permit framework simulation. |
| Setup | Start with no mock app selected, then another app selected. Show actionable setup; no simulation. Select Moving Traveler and retry. Reopening settings must not silently start playback. |
| Point selection | Set endpoints by tap, search and coordinates. Check negative coordinates, decimal validation, poles/date line, equal endpoints and invalid input. Missing points produce Choose start/Choose destination; those actions open selection. Static mode needs one point. Clear/swap endpoints and return to the correct planning stage. |
| Ordered via points | Add one, then six vias using search, map selection and coordinates. A seventh intermediate must not be added. Verify numbered map markers and start → via 1…6 → destination order. Change place, Move earlier/later and Remove must update the sequence and replan; Swap reverses the vias along with endpoints. Long-pressing a via near B must not drag B. Intermediate-point controls must not edit an active/pending session. |
| Direct route | Use equatorial points `(0, 0)` to `(0, 0.01)` at 36 km/h. Expect about 1,112 m total and 10 m/s progression. Check received fixes in a separate test receiver, including increasing timestamps, bearing, speed and mock flag. Compare distance against monotonic elapsed time, allowing observed callback latency. |
| Direct via geometry | Explicitly choose Direct line and create an L-shaped route with a via. The displayed and received path must traverse both straight segments through that via instead of cutting across the corner. The total distance/time includes every segment. Vias add no automatic pause or dwell. Stationary mode ignores hidden vias and holds only A. |
| Geoapify routes and modes | Fetch short real routes in Walk, Cycle and Drive in representative cities/countries. Verify requested profiles are `walk`, `bicycle`, `drive`; check known differences where data supports them. Returned geometry, snapped endpoints and arrival must agree. No-road/unsupported cases show failure; Retry route retries. Failure never fabricates a direct line. Try rural paths, one-way roads and a disconnected pair. |
| Route choices and selected playback | Where distinct paths exist, show Balanced/Shortest, plus Fewer turns only for Drive. Repeated geometry must not appear as fake alternatives. Select each loaded choice: its line becomes teal and distance/playback time change; no new routing request occurs. Start must pass that full selected geometry to the service, not always the first response. Rotate and confirm selection survives. A temporarily absent choice must not erase the user's remembered preference. |
| Provider via geometry | Verify requests use ordered coordinates, `intermediate_waypoint_mode=through_stop` and `optimize_stops=false`. Returned legs must meet without invented connectors and visit every via in sequence. Playback follows full road geometry continuously at the chosen pace, with no dwell. Using controlled responses, reject disconnected/missing/reordered legs and a snap over 1 km at any via or endpoint; warn for snaps over 50 m. Check the reported point number. |
| Pace independent of routing | Presets choose 5, 15 and 50 km/h and select a route mode. Editing custom pace must not change mode or refetch the route. Displayed playback time follows the chosen pace rather than Geoapify's duration estimate. No traffic or physical-footstep simulation is implied. |
| Pace | Check 0.5, 5, 15, 50 and 200 km/h; typed and slider controls agree. Change pace while moving and paused without restart/jump. Invalid text must block a new Start but must not block Pause, Resume, key setup, point selection or Retry route. Route preview reveals pace controls; route setup/loading must not falsely display a ready route. |
| Pause/resume | Pause for at least two minutes. Coordinates remain fixed, reported speed becomes zero and timestamps continue. Resume does not jump ahead for paused time. Repeat from app and notification. |
| Destination hold | Finish a short one-way trip. Show Arrived and keep publishing the destination with zero speed until Stop. No automatic restoration or silent route restart. |
| Back and forth | Choose Back and forth, run at least three legs. Reverse along the same geometry at each endpoint; bearing changes appropriately, and position does not teleport back to the start. |
| Static mode | Choose Stay at start. Destination/pace controls are hidden as intended; publish the selected point until Stop. Leaving/reopening the app preserves live-session display. |
| Provider coverage | Receive GPS, network and available framework fused updates. With optional coarse permission granted and Play Services available, separately subscribe through Google FLP. Verify simulated position, speed and mock marker on each. With coarse denied, Play Services missing or FLP failure, Android providers keep working and capability status identifies the skipped/unavailable Google path. |
| App switching | Start, switch to a receiver, return, rotate/recreate the activity and reopen from Recents. Playback is continuous; UI does not start a second service or edit the active route accidentally. Stop remains reachable. |
| Collapsed journey actions | In portrait collapse the sheet by tapping its heading and by dragging down. Confirm the current primary action stays visible in missing-point, routing-setup, loading, error, ready, running, paused and arrived states. Pause/Resume and Stop must work without reopening the form. Expand again and verify endpoints, selected travel mode, pace and route are unchanged. Collapsing must not start, pause, stop or reroute a journey. |
| Sheet gestures and rotation | Drag only the heading/handle: slow drags settle to the nearest position and deliberate vertical flings settle in their direction. Horizontal/diagonal swipes must not toggle the sheet. Cancel a drag or interrupt an animation with app switching/rotation; the screen must return to a usable position with visible actions. Scroll the form without dragging the sheet. Rotate from both portrait positions into the always-open landscape side card and back; restore the portrait choice and current plan/session, with no hidden primary action or repeated route request. |
| Pending start and rotation | Rotate with the optional-permissions explanation open, with an Android permission request open, and immediately after Start. Continue/Skip dispatches once; Back/cancel returns to a usable Start state. Cancelled explanations do not start playback on return. Retry after a previous service error. If a command times out, later commands must not be cleared by the old timeout. |
| Screen off | On real OEM hardware run Back and forth for 60 minutes with the screen off, default power settings and a receiver recording timestamps. Record gaps, distance/time error, battery change, thermal state, ANRs and service kills. Test stationary hold too. Wake-lock release must be observable after Stop. |
| Notification denied | API 33+: deny, dismiss and later revoke notification permission. Playback still starts from the visible app; in-app Stop works. Check system Task Manager visibility. Re-enable permission and verify notification Pause/Resume/Stop. |
| Mock permission revoked | During playback select a different mock app or clear the selection. No crash, stuck wake lock or false “running successfully” state; show the need to select this app again. Repeat after permission is restored. |
| Optional coarse permission | Grant, deny, deny permanently and revoke approximate-location permission in Settings. Google mock methods must not run without permission. Denial must not block framework playback; status distinguishes Google compatibility from Android providers. If Android kills the process on revocation, confirm no silent restart, then explicitly Start and verify framework fallback. Grant later and verify the Google path on a subsequent explicit Start. |
| Device Location toggle | Toggle system Location off/on before and during a run; capture OEM/provider behavior. Explain observed receiver failure without claiming successful delivery when none occurs. |
| Stop and cleanup | Stop in app and notification while running, paused, static and arrived. Test rapid Start/Stop/Start. Remove owned test providers, disable FLP mock mode and release wake lock; a receiver can recover real fixes when available. Record temporary receiver caches separately. |
| Process lifecycle | Swipe task away, kill the process, use system Stop/Force stop, and reboot. Distinguish behaviors: normal task dismissal may keep the ongoing service; process death/reboot must not silently resume an old route. Check provider recovery and no lingering wake lock. |

## Network, privacy and interface cases

- **Key setup/reuse:** On the installed blank-key APK open Settings → Routing access, save a personal key and perform search/routing without reinstalling. Return to Routing access: show Key saved/reused automatically and Done, with the saved plaintext absent. Replace key opens a blank optional field. Change endpoints/vias/profile repeatedly and relaunch; reuse the same encrypted key without prompting to paste again. Test 401/403 access rejection, quota, invalid walking requests and a temporarily unreadable Keystore separately; these must not silently erase stored access. Retry route uses the saved key. Replace/remove deliberately, and verify clearing app storage returns to setup. Never capture the key in evidence. A save confirmation or desktop AES fixture is not live access or Android Keystore verification.
- **Separate providers:** With no routing key the map must still work after consent. With OpenFreeMap unavailable, direct coordinate simulation remains usable. With Geoapify unavailable but the basemap working, show the relevant route/search error. Test both services offline, invalid DNS/TLS, HTTP 401/403/429/5xx, malformed/oversized geometry and timeouts. Use injected responses for error/load cases, not excessive live API requests. No retry flood or false ready state.
- **Cancellation and partial choices:** Change/remove/reorder vias or change a profile while route preferences are loading; the newest plan must win. Close/reopen or rotate a via search during a pending response; old results must not populate its replacement. Cancel online planning and destroy/rotate the activity; stale callbacks must not replace current state or refetch an already retained request. If extra choices fail or time out after one valid route, keep that route with an explanation; no callback may fire twice. After a timeout, Retry route must leave the lane usable. Start remains disabled while loading.
- **Routing budget/limits:** With controlled transport, verify a full replan attempts up to two preference calls for Walk/Cycle and three for Drive, including calls returning duplicate geometry. Choosing a loaded choice, changing only pace and Pause/Resume must make none. Live credits also depend on waypoint pairs and distance; record actual account usage without exposing credentials. Test invalid/long walking requests as distinct from missing keys. Adding closer vias may reduce leg length but must not promise a route across missing access. Current per-leg provider limits and their primary source are in [Routing setup](ROUTING-SETUP.md).
- **Search:** Test empty/long/non-Latin names, duplicate names, coordinates, results near the date line and incomplete data. Search results must identify the selected place clearly. Clear search must empty the field/results without changing endpoints; the control is unavailable when the field is empty. Keyboard Search must submit the current query or coordinate action, without duplicate requests or duplicate point selection. Close and system Back must dismiss the picker without selecting an old result. Reopen and rotate with a draft query, visible keyboard and a pending response; restored input and results must belong to the current picker. Check keyboard overlap, scrollable results, map-selection access, attribution/link behavior and no query after the picker closes. Repeat with personal account restrictions enabled: browser origin/referrer rules must not be mistaken for native-app authorization.
- **Worldwide coverage:** Record short real Walk/Cycle/Drive routes in each priority region, including India, plus rural and disconnected cases. Successful samples prove those samples only. Confirm route duration is calculated from the chosen playback pace, not represented as live congestion time.
- **Online switch:** Disable during map loading/search/routing and active playback. Cancel pending work and ignore stale results; loaded local playback continues. Verify new planning requests stop, while distinguishing in-flight requests and independent Android/Play Services traffic in captures. Re-enable deliberately and confirm recovery.
- **Storage/privacy:** Manual-only vias must restore in order. Provider-derived vias, search labels and loaded route choices/geometry stay in memory. If any via is provider-derived, saved storage must omit all plan coordinates, including manual endpoints, rather than restore a trip missing that via. Opening such a point and accepting unchanged prefilled coordinates must preserve its provider provenance. Rotate to retain the live plan, then finish/relaunch and inspect the deliberate loss of the provider plan. Stop alone need not erase it. Verify encrypted-key storage, disabled backup and absence of keys/request URLs in logs/source artifacts. Map cache is separate; document observed storage. Clearing data removes preferences/consent/key. Compare actual traffic with the final policy and provider records; do not claim provider processing is unlogged or ephemeral.
- **Attribution/licenses:** Confirm OpenStreetMap/OpenMapTiles credits remain visible and clickable on the native map. Geoapify credits must accompany route/search content, including an already-loaded plan with the map hidden. Check final HTTPS privacy/terms/source links and generated dependency-license metadata. Inspect the release APK for current providers and absence of retired Google Maps/Firebase configuration.
- **Map behavior:** Test pan/zoom/rotation, selecting points, route fitting, antimeridian routes, follow behavior during playback and returning to the map after recreation. The full-screen map extends behind the floating header and sheet; fitted route endpoints, traveler and map credits must remain accessible in the visible area in both sheet positions and landscape. Confirm sheet movement does not repeatedly refit the camera or cause the route to jump. The real-location component must remain disabled. Test without Play Services to separate map display from optional mock compatibility. Check the actual native renderer and ABI/page-size compatibility on supported devices.
- **Interface/accessibility:** Use TalkBack, keyboard, large font/display scaling, portrait/landscape, small screens, dark system setting, cutouts, navigation bars and the open keyboard. Point rows, route status, grouped Walk/Cycle/Drive controls, pace and primary action must not overlap. TalkBack must announce each mode's selection, identify the search field, Clear and Close independently and offer Expand/Collapse on the portrait heading. The landscape heading must not expose an unavailable collapse action. Hidden collapsed form controls must not trap focus; the primary action and active-session Stop remain reachable. Check setup, route loading, error and ready states individually, and confirm disabled controls are understandable. Native widget screenshots without map tiles are not proof of live map rendering.
- **Haptics and animation preferences:** Test system haptics enabled/disabled on a real device. Important taps/selections and sheet-heading taps provide brief feedback when allowed; programmatic rendering, continuous sheet dragging and map motion do not vibrate repeatedly. Disable system animations and test tap/drag settling; the controls must reach a usable final state without waiting for a disabled animation. Repeated taps must not leave the sheet halfway open or duplicate playback commands.
- **Performance:** Profile the signed release during panning, routing, rapid point/profile changes, pace dragging, six-via editing and multiple 20,000-point fixture routes. Changing only traveler position must not rebuild static route/alternative layers. Record timings, memory/CPU, battery, ANRs and crashes. Agree measurable release thresholds; desktop rendering or one phone does not establish universal smoothness.

## Third-party app and WhatsApp verification

First use a test receiver that deliberately accepts mock locations. Then test an app that rejects them: rejection is a supported compatibility limitation, not a reason to conceal the mock flag. Record app/version/provider and observed result individually.

WhatsApp is **not verified by this document**. For a consented test using your own accounts/devices, tell the recipient the location is simulated. Start a Moving Traveler route, then manually use WhatsApp **Attach → Location → Share live location**. Watch from the receiving device; record update cadence, motion, pause, destination hold and Stop recovery. A “Send current location” message is static and cannot establish moving-location compatibility. Stop the test share manually afterwards. Repeat with app switching, screen off and current WhatsApp permission settings. [WhatsApp live-location instructions](https://faq.whatsapp.com/480865177351335/?cms_platform=android)

A successful result applies only to that tested combination. Publish no universal compatibility claim, and do not automate messaging, access private chats or bypass mock detection during testing.
